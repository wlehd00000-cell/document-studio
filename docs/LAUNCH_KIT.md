## English

**Document Studio: reusable Codex skills for business reports and proposals**

Do you keep rewriting the same instructions for report structure, wording, layout, and checks? Document Studio packages those steps as reusable Codex skills, with Japanese and Korean language modules and an optional workflow for reviewed company conventions.

Start with one fictional, two-page HTML proposal. The repository includes the install command, a complete first brief, and no-install document examples. An editable PowerPoint export workflow is available, but rendering and editability need checking in your environment. This is experimental alpha software; private-source company-pack distribution is not supported.

Try it: https://github.com/wlehd00000-cell/document-studio/blob/main/docs/TRY_FIRST.md

If the workflow is useful, Star the repository to save it. If you try it, share the step you reached and what needed fixing; installation failures are useful feedback too.

## A focused demonstration

Use one actual attempt, including any failures:

1. Show the complete [first-task brief](TRY_FIRST.md#first-task), the agent/model used, and the date.
2. Show that the installed agent discovers `report-html-pptx`; a downloaded ZIP alone is not installation evidence.
3. Show the resulting HTML and one concrete revision, if needed. Label a static showcase as a static showcase.
4. Explain which checks ran and which did not. If showing PowerPoint, open the actual exported file and demonstrate a text edit.
5. End with the repository link and an optional invitation to Star or report feedback.

Use fictional inputs and show no account identifiers or private files. Do not present a prepared static example as a live generation, or claim time savings, adoption, or cross-model superiority without measurements.

## Distribution notes

Share where reusable agent skills and document workflows are relevant, following the destination's submission rules. State your relationship to the project when submitting as its maintainer. Check for existing submissions before sending another. A pending submission is not an accepted listing or endorsement.

For feedback, ask for the environment, furthest completed step, blocker, and whether the user would try it again. The [feedback template](../.github/ISSUE_TEMPLATE/first_run.md) also asks where they found the project. GitHub Stars, release downloads, installations, and successful document creation are different measures.
