# 管理者向け：会社別プラグインを評価する

Document Studioは、**承認した会社ルールと文書制作スキルをまとめ、会社別プラグインのパッケージを作るためのオープンソース実験**です。管理者が準備するものと、社員の依頼後に動く制作工程を分けて評価してください。

[日本語の全体像](https://document-studio-public-experiment.wlehd00000.chatgpt.site/) · [内部スキルの流れ](https://document-studio-public-experiment.wlehd00000.chatgpt.site/#plugin-flow) · [文書ガイド一覧](README.md) · [ソース](../README.md)

## まず知っておく現在の範囲

| 項目 | 現在の状態 |
|---|---|
| 架空Packのパッケージ出力 | 同梱の独立した例で評価可能 |
| 実在資料からの公開配布用パック | 公開資料で、配布許可・権利・承認条件を満たしたものに限定 |
| 非公開の社内資料から内部だけに配布 | 現在の公開エクスポーターでは未対応・拒否対象 |
| インストール・公開 | パッケージ生成とは別。導入先の対応機能と管理者権限が必要 |
| 新規の文書生成・HTML/PPTX品質 | 導入先で別途実行し、実際の表示・書体・編集性を確認 |
| ワンクリックの社内導入・検証済み全自動出力 | 未提供 |

これは実験段階のalpha版です。会社全体の生産性改善、モデル間の同一品質、任意HTMLの完全なPowerPoint再現を実証した製品ではありません。非公開資料を公開扱いに変更してエクスポートを通す方法は使用しないでください。

## 管理者が用意するもの

1. **利用できる参考資料と権利の確認**：文体・デザインの参考にするPDF/PPTXと、分析・配布の対象範囲を整理します。
2. **承認する基準と責任者**：用語、文体、デザイン、出典、検討基準を確認します。提案をそのまま会社の公式ルールと扱わず、Company PackのID・版と承認を管理します。
3. **評価する環境と担当者**：スキル/プラグインの導入権限、生成・ブラウザー確認・必要なPPTX出力環境を用意します。パッケージ出力、導入、新規依頼の確認は別工程です。

公開パッケージは元のPDF/PPTXとフォント本体を同梱しません。導入時の権利・書体・依存関係の確認は別途必要です。[管理者向け詳細](WORKSPACE_ADMIN_GUIDE.md) · [資料分析からパックを作る手順](DEMO_FLOW.md)

## 配布したプラグインには何が入るか

**Company Pack＋基本スキル8個＋選択した日本語/韓国語モジュール＋導入/ファイル検証用スクリプト**をまとめます。

Company Packは承認した規則と根拠のまとまりです。会社別依頼では `report-html-pptx` が、使用する承認済みPackを明示的に選択・検証し、必要な制作処理へ渡す設計です。エクスポートしたREADMEは、同梱したPackの場所と `--company-pack` 指定を案内します。ZIPが存在するだけで、Packの自動適用や導入成功を確認したことにはなりません。

| 役割 | スキル | 主な仕事 |
|---|---|---|
| 管理者の資料分析 | `company-profile-analyzer` | 参考資料の特徴・根拠、Company Packの確認と承認 |
| 制作の窓口 | `report-html-pptx` | 目的・読み手・言語・形式、会社Packの選択、工程の引き継ぎ |
| 構成 | `document-architecture` | 文書の目的と読み手に合う情報順序 |
| 必要な調査 | `document-research` | 主張や原稿を変える根拠の確認 |
| 執筆 | `document-writing` | 原稿・見出し・注記と条件の整理 |
| HTMLデザイン | `document-design` | 実際の組版、本文・図表・画像の関係 |
| 必要な画像制作 | `visual-assets` | 意味のある画像・図版の制作 |
| PowerPoint出力 | `html-to-pptx` | 実測した位置や文字からPPTXへ構成し、出力を確認 |

`business-japanese-translation` / `business-korean-translation` は選択導入です。対象言語に応じて校閲・翻訳を行います。未導入の専門校閲を実施済みと報告する設計ではありません。

## 社員の1件の依頼はどう進むか

> 社員の依頼 → 制作の窓口・会社Packの選択 → 構成と必要な調査 → 執筆と言語確認 → デザインと必要な画像 → 実際のHTML確認 → 求める形式の出力と最終確認

導入先のAIが役割別の指示とスクリプトを適用します。すべてのスキルを毎回同じ順序で実行する無人サービスではなく、内容と不足情報に応じて工程を選ぶ設計です。

- 根拠不足なら調査し、構成・原稿に戻します。画像制作も具体的な説明に必要な場合に行います。
- 原稿のみ・HTMLのみの依頼は、その成果物の確認までで完了します。PPTXを求める場合は変換と実表示・文字保持・編集性の確認を行います。
- 部分修正は影響する担当と、その後の確認を更新します。以前の確認を、変更後の成果物にそのまま流用しません。
- 不明な社内情報は作りません。必要な条件を確認し、未確認の範囲を報告します。
- 任意のコンサルティング企画は明示的な選択時のみ使い、方向性と最終原稿の確認後に本制作へ戻ります。

実際の工程と条件は [制作の窓口の仕様](../skills/report-html-pptx/SKILL.md)、収録内容は [スキル一覧](TECHNICAL_GUIDE.md#whats-included-8-core-skills--2-optional-languages) を確認してください。

## 最初は同梱の架空Packで評価する

ソースを取得し、[導入手順](../INSTALL_INSTRUCTIONS.md)でPythonと必要な依存関係を確認します。リポジトリのルートで次を実行します。

```bash
python scripts/install_local.py --verify-only
python scripts/export_company_plugin.py --company-pack company-packs/demo-retail --language-skills ko,ja --output ./dist/demo-retail-documents.zip
```

1. ZIPとマニフェストを確認します。これだけではプラグインはインストールされません。
2. 権限のあるアカウントで、[対応する導入手順](../skills/company-profile-analyzer/references/account-installation.md)に従って導入します。
3. **新しい依頼**で、使用PackのID・版、生成した原稿/HTML、実施した確認を見ます。PPTXが必要なら実際の出力と編集性も確認します。
4. 会社ルールの適用、修正した箇所、未確認の範囲を記録します。モデル・プラグイン・Pack更新後も再評価します。

[公開作例](SHOWCASE.md)は構成や表現を説明する静的HTMLです。新規プラグイン導入やPPTX検証の成功記録ではありません。実際の結果や問題は、公開可能な範囲で[フィードバック](https://github.com/wlehd00000-cell/document-studio/issues/new?template=first_run.md)として共有できます。
