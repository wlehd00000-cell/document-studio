# Document Studio

**次の報告書にも使える、資料作成のワークフロー。**

報告書・提案書・プレゼン資料を作るたびに、文体や構成、確認基準を説明し直す。Document Studioは、調査・構成・執筆・デザイン・確認の手順をエージェント用スキルにまとめ、次の作業でも使えるようにします。

[English](../README.md) · [한국어](QUICKSTART_ko.md) · [構成を見る](SHOWCASE.md) · [ドキュメント一覧](README.md)

MITライセンスのオープンソース · 実験版 alpha.6 · Codexおよびプラグイン作成権限のあるChatGPTアカウント向け

## 再利用するもの

**スキルは作成手順を、Company Packは確認済みの会社別ルールを保持します。**

スキルには、読者と目的の確認、根拠の調査、執筆、視覚的な構成、成果物の確認といった作業指針が入っています。用語・配色・配置の原則を会社別にそろえたい場合は、担当者が確認したCompany Packを併用できます。新しい資料の読者と内容は、その都度の依頼に合わせて決めます。

まず一般的な資料を1件作り、会社別ルールが必要になったらパックを追加してください。

## 導入方法

### Codex

Node.js 22.20以降とGitを用意し、**自分の作業プロジェクトのフォルダ**で実行します。

```bash
npx --yes skills add wlehd00000-cell/document-studio --skill '*' -a codex --copy -y
```

新しいCodexセッションで `report-html-pptx` が認識されるか確認してください。この方法では10個のスキルを配置します。会社別ZIPの作成ツールも使う場合は、[ソース全体の導入手順](TRY_FIRST.md#local-codex)を参照してください。

### ChatGPT

Plugin Creatorとプラグイン作成権限のあるアカウントで、[Starter ZIPの登録手順](TRY_FIRST.md#chatgpt)に従います。保存されたプラグインのURLとIDを確認し、新しい会話で選択してください。

## 最初の依頼

導入したスキルまたはプラグインで、次の依頼を試してください。

> Document Studioを使い、架空企業の新入社員オンボーディング改善提案書を、日本語のHTMLで2ページ作成してください。読者は業務責任者です。12名を対象とした4週間の試行の承認を求めます。仮の予算は30万円です。
>
> 1ページ目に課題・提案・期待効果、2ページ目に日程・予算・評価指標3つ・リスクをまとめてください。
>
> 数値は仮定と明記し、実在企業の資料は使わないでください。HTMLファイルと、実際に実施した事実確認・表示確認の結果を提示してください。

求める判断が明確か、予算と日程が整合しているか、文字が切れていないかを確認します。実施できなかった確認項目も、結果に明記されているか見てください。

## 会社別ルールを追加する

架空の[小売企業パック](../company-packs/demo-retail/pack.json)と[製造企業パック](../company-packs/demo-manufacturing/pack.json)で形式を確認できます。自分で作る場合は、**利用権限のあるPDF/PPTX → 根拠の抽出 → 担当者の確認 → Company Packの承認 → 新しい資料の作成**という順序で進めます。

公開配布の要件を満たす承認済みパックは、スキルとともにプラグインZIPとして書き出せます。[分析・確認の手順](DEMO_FLOW.md)と[技術ガイド](TECHNICAL_GUIDE.md)をご覧ください。

## 現在の対応範囲

- PDF/PPTXからの根拠の抽出、会社別ルールの確認・承認、公開配布が許可されたパックのZIP書き出しに対応しています。
- HTMLの表示、フォント、編集可能なPPTX、アカウントごとの導入は、実際の利用環境で別途確認が必要です。
- 非公開・利用制限のある資料に由来するパックの書き出しと、ワークスペースへの自動公開には対応していません。

成果物は利用するAIと制作環境の影響を受けます。品質向上率や時間短縮率は確立されていません。[評価と制約](TECHNICAL_GUIDE.md#evaluation-and-limitations)で、確認済みの範囲をご覧ください。
