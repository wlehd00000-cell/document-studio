# Fixed HTML composition and default PowerPoint export

All DEMO document composition uses HTML. Canonical source is html/index.html with project-relative html/assets. **HTML is the assembly and editable-overlay route, not the exclusive illustration medium**: source photography, official assets, generated conceptual scenes and raster/vector artwork may be embedded when they better express a subject. Choose each visual's medium before intensive CSS/SVG work, keeping precise copy, charts and interactive/motion elements native where useful. Default delivery is editable PPTX using the packaged [HTML-to-PPTX skill](../../html-to-pptx/SKILL.md). A capability or creativity comparison cannot reopen these choices.

Reading, live and office-print profiles affect density/canvas/type, not technology. Bare PPTX uses a provisional reading profile; ask about use only when it changes a consequential content decision. A PPTX/Slides template or legacy native_capability_verified/native_creative_review flags cannot select native authoring. Preserve actual template constraints while composing the changed scope in HTML.

## Only explicit output requests change export

| User's current or accepted output request | Adapter from the same HTML |
|---|---|
| No special request, or PPTX | Packaged HTML-to-PPTX |
| PPTX and PDF | Packaged converter plus HTML-to-PDF |
| PDF only | HTML-to-PDF |
| HTML/browser only | HTML and relative assets; responsive behavior if requested |
| Word/DOCX or other special output | Available output adapter from the reviewed HTML/copy, with actual file inspection |

Record the request and exporter in the same brief. Source templates, alternate capability and missing tools do not create an export exception. Do not silently drop a requested file, switch authoring or substitute a screenshot deck.

## Runtime and scope

authoring_routes.py always returns html_report and export adapters. It does not certify capability. Check only the selected exporter when needed and reuse known runtimes. If unavailable, finish HTML/unaffected work and state the genuine file boundary. Additional installation or a changed deliverable is a concrete final user decision, not a startup preferences interview.

Revisions reuse valid HTML and accepted constraints. If an older project has no HTML, reconstruct only the affected scope, preserving originals and layout intent. Font/CSS/canvas/data/asset changes reopen actual dependents through [project state](project-state.md); local edits do not reopen unrelated research/onboarding. A missing final renderer leaves export visual review unverified.
