# Reader, language and delivery choices

This reference owns consequential intake choices under [the orchestrator](../SKILL.md), not the actual language implementation. Reuse explicit/accepted answers and ask only a branch that materially changes the file. Nationality/location do not establish document language or style.

| Trigger | Resolve if genuinely unknown |
|---|---|
| Several readers | Primary decision-maker, execution reader and relevant prior knowledge |
| Headquarters and branch | Shared context and the actual entities meant by "we/head office" |
| External recipient | Role, relationship, decision criteria and disclosure scope |
| Korean and Japanese deliverables | Separate files, paired text, or a main file plus translated summary |
| Live and independent reading | Presenter explanation, standalone detail and requested uses |
| Format uncertainty | Editing, screen, print/share and required file output |
| Vague style preference | Useful actual example and what to retain or avoid |

Record conversation/source/deliverable languages separately and necessary reading/relationship/disclosure choices in brief.communication. Style examples and subjective priorities stay with this document. Explicit delegated non-mode choices can be recommended and recorded according to the intake gate. Do not ask staff to design pages or infer accepted style from nationality.

Writing applies these choices through [language and register](../../document-writing/references/language-and-register.md). Architecture applies them to argument/detail; design to density, language geometry and visual freedom. Bilingual equivalence and actual language-specific text remain their respective checks. Required questions/checkpoints live only in [intake](intake-and-collaboration.md).
