# 문단과 실제 행의 읽기 흐름

활자와 밀도 수치의 정본은 [디자인 시스템](../system/design-system.md)과 `system/design-tokens.json`이다. 상세 읽기 보고서의 작은 활자를 발표 기본값으로 확대하지 않고, 표지·opener에 본문 밀도를 강제하지 않는다. 일괄 축소 금지는 넘침을 덮기 위한 추가 축소에 적용한다. 선택한 프로필의 최종 물리 크기에서 문단·표·직접 라벨·캡션과 한일 줄 흐름을 확인한다.

문서 레이아웃을 만들거나 줄바꿈·경어·폭·폰트 변경을 검토할 때 읽는다. 일본어·한국어 파일에 모두 적용하되 언어별 조판은 구분한다.

한국어 문서는 [한국어 문단·어절·의미 단위 기준](../../document-writing/references/demo-esg-korean-lineflow.md)을 함께 적용한다. 자연스러운 장문 원고와 실제 행 편집은 서로 다른 확인이다. 원본 PDF의 물리적 개행을 정본 문단이나 HTML `<br>`로 가져오지 않는다.

## 세 층을 따로 확인

1. **원고와 문단:** 같은 논점의 문장을 연결하고 논점·행동·조건이 바뀔 때 문단을 나눈다. 구절마다 줄을 내려 설명을 조각내지 않는다. 제목·표·라벨의 명사형과 본문의 완결된 문장은 역할이 다르다.
2. **조판:** 실제 언어 태그와 글꼴, 금칙, 필요한 고유명사·숫자/단위를 확인한다. 한국어 keep-all은 한국어에만 적용한다. 일본어는 적합한 기본 개행을 쓰며 line-break:strict만으로 의미 흐름이 해결됐다고 보지 않는다. lang=en 전체나 문단 전체를 nowrap으로 묶지 않는다.
3. **실제 행:** 출력 크기에서 문장을 읽는다. 핵심 용어/서술어의 불편한 분리, 다음 문장 몇 글자만 앞줄에 붙는 경우, 짧은 꼬리줄, 조건과 주장의 분리, 제목·표·주석의 읽기 흐름을 본다. 정상적인 일본어 개행을 전부 오류로 판정하지 않는다.

예: 「購入につなげます。対／象店舗は確認が必要です。」라면 두 번째 문장을 다음 행으로 옮기는 것이 읽기에 나을 수 있다. 「案／内します」「認／知率」도 중요도와 폭을 보며 조정한다. 모든 단어 보호, 모든 문장 한 줄, 모든 구절 새 줄은 기본 규칙이 아니다. 짧은 꼬리줄 글자 수는 경고 후보이며 합격 점수가 아니다.

## 수정 순서

원고의 논리와 조건 확인 → 실제 렌더에서 문제 행과 원인 확인 → 폭·열·배치 조정 → 필요한 문장/의미 단위 이동 → 사실과 조건을 보존한 간결화 또는 국소 글자 크기 조정 → 공간 부족 시 내용 재배치/분량 조정 → 변경 페이지 재렌더.

의미 단위 이동은 수식어와 대상, 주체와 서술어, 숫자와 조건의 관계를 보존한다. 사용자 제약에 맞는 폰트 조정은 활용하되 전체 글자를 일괄 축소하지 않는다. 페이지 수 변경은 기존 모드와 제약을 따른다.

고정 A4의 선택적 행 고정은 현재 글꼴·폭에서 측정한 경우에만 쓴다. 문장·경어·폰트·폭이 바뀌면 다시 측정한다. 반응형 HTML이나 다른 크기의 파일에 그대로 복사하지 않는다. 원고는 개행 마크업 없는 내용으로 유지하고, 레이아웃의 개행 이유만 필요할 때 기록한다.

## 재사용 가능한 HTML 렌더/행 검사

### 원고 문단과 PowerPoint 줄의 계약

새 DEMO HTML에는 `data-pptx-text-flow="natural"`을 사용한다. 자동으로 감긴 브라우저 행은 PPT 문단이나 강제 줄내림으로 굳히지 않는다. 실제 `<p>` 문단과 의도한 `<br>`는 구분하며 `<br>`는 문단 안의 `a:br`로 변환한다. 이전 HTML은 측정행 유지 경로와 호환되고, 필요한 고정 행은 해당 요소의 `data-pptx-text-flow="measured"`로 한정한다. 모든 행 고정이나 전면 nowrap은 기본값이 아니다.

일본어에서는 `購入につなげる`, `来場者`, `ワークショップ` 같은 핵심 의미 단위와 숫자·조건의 관계를 확인한다. 상품명 나열 뒤 운영 조건, 설명 뒤 적용 조건, 업무 단계 사이의 제한적 줄내림은 공간보다 읽는 순서를 개선할 때 선택한다. 원문·수치·책임·확정 상태를 대조한다. 줄내림 뒤 실제 PowerPoint 글자 높이, 상자 높이, 인접 블록과 푸터 간격을 재확인한다. 추가 행을 기존 상자 밖으로 흘린 채 성공으로 판정하지 않는다.

이 판단은 2026-10-02 DEMO EVENT 원 제작본과 사용자 편집본의 실제 PowerPoint 비교에서 관찰했다. 사진 원본 바이트는 유지됐고, 본문·표의 글자는 보존한 채 의미 경계로 줄을 옮겼다. 특정 치수나 개행을 모든 문서의 고정값으로 만들지 않으며, 별도 캡션 축약·출처 삭제를 일반 규칙으로 확대하지 않는다.

사용 가능한 Playwright Python 런타임에서 실행한다. 신규 설치는 자동 수행하지 않는다. Python이 없어도 다른 가용 렌더러에서 동일 기준을 적용한다. 직원에게 도구 설치를 맡기지 않는다.

Python Playwright를 이용할 수 없고 기존 Node Playwright가 있으면 같은 측정 코드를 사용하는 `render_text_flow.mjs`를 실행한다. `--playwright-module`에는 발견한 기존 패키지의 진입점만 지정하며 설치나 외부 내려받기를 수행하지 않는다. `--browser-path`는 확인한 기존 브라우저 경로를 사용할 수 있다. 결과의 검토 상태는 Python 경로와 동일하게 pending으로 시작한다.

```text
python scripts/render_text_flow.py <input.html> --output-dir <project>/qa/text-flow --revision <current-revision>
node scripts/render_text_flow.mjs <input.html> --output-dir <project>/qa/text-flow --revision <current-revision> --playwright-module <existing-playwright-entry>
```

- 기본 페이지 탐색: [data-pptx-slide], [data-fixed-page], .page, .slide. 다른 문서는 --page-selector를 지정한다. 페이지 수/브랜드/개인 경로에 의존하지 않는다.
- --pages 2,4로 변경 페이지만 검사한다. 전역 글꼴·폭·자산·순서 변경은 전체 검사한다. 선택되지 않은 페이지를 검토했다고 보고하지 않는다.
- --protected-term YOUUS처럼 필요한 용어만 반복 지정한다. --terms-json은 문자열 배열이다. 긴 용어 묶기가 넘침을 만들면 폭/배치를 먼저 고친다.
- --content-selector / --boundary-selector로 본문과 주석/푸터 경계를 지정하면 충돌 후보도 수집한다. 없는 경계는 추측하지 않는다. --block-selector로 본문 블록을 추가할 수 있다.
- 페이지 선택자가 비었거나 선택한 페이지가 모두 숨겨졌으면 측정을 거부한다. 숨겨진 페이지나 측정할 텍스트가 없는 페이지를 포함하면 coverage_status=incomplete로 기록한다. 필요한 라벨은 data-text-flow나 --block-selector로 지정한다.
- 결과: text-flow-audit.json, 실제 크기의 page-N.png, 요약. 행 텍스트·위치·사용 폭, 스크린/인쇄 구조, 로드 실패, 소스/로드된 로컬 자산 해시를 기록한다.
- 각 문자의 DOM Range 사각형으로 `drawn_bounds`를 기록한다. 고정 상자 밖으로 추가 행이 그려지는 `vertical-glyph-overflow`, 페이지 밖 문자, 다른 텍스트 소유자의 행 충돌을 수집하고, 푸터 경계는 상자와 실제 행의 아래쪽 중 더 큰 값으로 비교한다. 문자 사각형은 글꼴의 실제 픽셀 윤곽이 아니므로 자동 측정만으로 보이는 먹선·정교한 가림·의미 있는 크롭을 보증하지 않는다. 의도한 editorial 문자 중첩은 `data-text-flow-overlap-reason`으로 이유를 남기며 실제 시각 검토 대상인 warning으로 유지한다.
- 이미지·SVG·canvas는 `visuals`에 실제 viewport/visible bounds를 기록한다. 실제 overflow clip 조상을 존중하므로 full-image cover의 의도한 큰 사진 크롭은 허용한다. clip 밖으로 페이지를 침범하는 그림은 `visual-outside-page` finding이며 SVG의 visible getBBox도 확인한다. CSS mask/clip-path, 그림의 의미·focal point, 픽셀별 alpha 경계는 별도 시각 검토가 필요하다.
- status=measured는 자동 측정 완료다. visual_review와 editorial_review는 pending이며 실제 이미지를 읽고 기록하기 전에는 PASS가 아니다. 금칙·꼬리줄·용어 분리·문장 도입 조각은 편집 경고다. 가로 넘침·세로 잘림/스크롤·자산 실패·경계 충돌은 화면과 인쇄 양쪽에서 수집하고 실제 영향과 원인을 확인해 판정한다.
- 한국어는 실제 글자 위치와 원문 오프셋을 대조하여 `korean-eojeol-split`, `korean-number-unit-split`, `korean-punctuation-start`, `korean-opening-punctuation-end`, `korean-short-tail`, `korean-manual-body-breaks`, `korean-language-tag` 후보를 수집한다. 띄어쓰기에서 자연스럽게 감긴 행과 어절 내부 분할을 구분한다. 글자/단위가 다른 인라인 요소에 나뉘어 있어도 확인하며 선택적 보호 용어도 기존 방식으로 검사한다. 각 블록의 word-break/overflow-wrap/white-space/line-break 및 수동 개행 수를 기록한다.
- 대표 페이지의 실제 행을 읽고 경고를 수정/문맥상 허용/미확인으로 판단한다. 자동 경고가 없다는 사실은 한국어 문장 연결·의미 단위·짧은 꼬리 행의 편집 검토를 대체하지 않는다. 원고·폭·폰트·크기·자간·행간·최종 형식 변경 후에는 영향 페이지를 다시 확인한다.
- --timeout-ms로 자산 준비 대기를 제한한다. 캡처 교체 중 실패하면 failed 상태를 기록하므로 이전 완료 기록을 현재 검수에 쓰지 않는다.
- --check-against <prior-audit.json>은 소스/로컬 자산·측정 코드·저장 이미지 변경을 확인하며 미완료 기록은 거부한다. 검수 재사용 시 viewport·출력 크기·폰트·외부 자산도 대조한다. 변경된 결과는 stale이다. 외부 자산의 내용은 해시 검증하지 못한다.

번호·라벨의 위치 CSS는 전용 클래스나 직접 자식 선택자로 범위를 제한한다. 넓은 `span` 선택자는 한일 번역 문구까지 절대 위치로 바꾸어 제목·설명·번호를 겹치게 할 수 있다. 넘침이 없더라도 실제 화면에서 필요한 문구가 보이고 서로 겹치지 않는지 확인한다.

글꼴 로딩 완료만으로 승인된 실제 글꼴과의 일치를 보장하지 않는다. 전체 흐름과 밀집/긴 제목 페이지를 먼저 보고 후속 수정은 영향 범위만 본다. 반복 수선 시 원고·컨테이너·폰트·변환 중 원인을 다시 분류한다.

## 경고별 완료 기준

[완료 품질](completion-quality.md)의 처리 기록을 적용한다. 화면·인쇄에서 같은 page/block/warning으로 나온 후보는 하나의 항목으로 묶고 관측 모드를 남긴다. 각 항목의 실제 행을 읽어 문맥상 허용 또는 미확인으로 판단한다. 수정한 항목은 최신 원고로 재측정해 해소됐는지 확인한다. 전체 페이지를 봤다는 일반 문구만으로 경고를 해결하지 않는다.

## 파일 변환과 현재 기록

HTML과 PPTX의 개행은 별도로 확인한다. PPTX는 실제 PowerPoint/LibreOffice 렌더에서 행과 목록·표·숫자 설명을 본다. 원고 문제는 정본과 authored HTML, 변환 전용 문제는 audited 사본에 수정한다.

현재 qa 요약에는 revision/fingerprint, 검사 페이지, 도구/폰트/크기, 자동 측정, 실제 시각 검토, 행 편집 검토, 미확인 범위를 구분한다. brief의 현재 revision과 해당 체크포인트를 함께 갱신한다. 변경된 결과물에 과거 사용자의 승인을 새 승인으로 옮기지 않는다. 과거 이력은 보존하고 현재 상태 요약과 분리한다.

기준 출처: [W3C CSS Text](https://www.w3.org/TR/css-text-3/#line-break-property), [日本語組版処理の要件](https://www.w3.org/TR/jlreq/). 표준 조판 규칙과 문서별 편집 판단을 구분한다.


## 의미 단위 줄내림을 먼저 판단한다

[사용자 수정에서 확인한 줄내림 기준](../../document-writing/references/semantic-linebreaks.md)을 적용한다. 안내·요청문·짧은 읽기용 설명은 문장 기능이 바뀌는 지점을 실제 줄에 반영한다. 자동 경고가 없어도 이 판단을 생략하지 않는다. 본문의 모든 마침표 뒤에 줄을 넣거나 브라우저의 모든 물리적 줄을 고정하지 않는다. 같은 기능의 문장은 이어 쓰고, 기능 전환은 독립된 읽기 단위로 시작한다. 추가 행의 높이·인접 영역·하단을 다시 확인한다. editorial/export의 `semantic_breaks` 기록에는 실제 나눈 기능 또는 나눌 필요가 없는 이유를 적는다.
