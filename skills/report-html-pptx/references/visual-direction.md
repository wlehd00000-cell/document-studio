# Visual explanations for document files

For DEMO work, use [DEMO chart/table implementation](demo-esg-chart-table.md) and the relevant [DEMO cases](demo-esg-casebook.json) first. Keep the evidence rules below; use the 72-pattern library to resolve an actual encoding need rather than overriding the strong DEMO reference with a generic chart design.

Build the visual from **reader question → supported relationship → form → labels → composition**. Purpose profile and cover/chapter/body family follow [the canonical system](../system/design-system.md). Art direction can use full-image scenes, strong crops and quiet title areas without implying factual evidence. Art direction, density and craft belong to [document design quality](document-design-quality.md); this reference owns evidence and visual encoding.

This is the encoding reference for [document design](../../document-design/SKILL.md). Architecture defines the visual purpose, research supplies actual evidence/assets, and design chooses form/composition and briefs the separate visual-assets specialist. Do not duplicate the producer's image prompts here.

## Choose the relationship

| What to understand | Useful forms | Conditions to establish |
|---|---|---|
| Difference among values/options | Bar/dot chart, shared-criteria table | Common units/baseline/criteria, order and real differences |
| Change over time | Line chart, dated milestones | Comparable periods, spacing and missing observations |
| Parts of a whole | Stacked bar, proportion graphic | Real total/denominator and legible segments |
| Paired measured variables | Scatter plot | Axes, units, scope; correlation is not causation |
| Sequence/dependency | Directed flow, process diagram | Arrow meaning, prerequisites, branches and end state |
| Owners/handoffs | Swimlane, responsibility matrix | Owner, handoff and authority |
| Schedule/capacity | Timeline/Gantt, resource table | Dates, duration, dependencies; committed vs proposed |
| Concept/system | Grouped or layered map | Boundaries, components and actual connections |
| Proposed experience | Storyboard, annotated mockup | Sequence, proposed vs confirmed |
| Place/movement | Annotated supplied plan/map | Source geometry, path and scale |
| Evidence/object identity | Source photograph/packshot, detail enlargement | What to notice, source, conditions and caption |

Choose prose/table when more direct. Sparse evidence does not justify invented numbers or unsupported magnitude through lengths, areas or scores. Qualitative relationships stay qualitative. DEMO ESG is a composition reference, not a requirement for ESG charts on every page.

## Key visual alternatives

Use the selection preference and checkpoints from [intake](intake-and-collaboration.md). One-shot chooses directly; delegated recommended mode uses the recommendation. Compare only when the user chooses comparison, concentrating on central evidence/concept/ownership decisions. Do not open another questionnaire for colors or ornaments.

Retrieve a few evidence-compatible candidates from the [72-pattern local library](visual-reference-library.md); inspect only relevant thumbnails/entries. The library offers starting points, not a ceiling on original composition. If an unfamiliar relationship needs a new treatment, adapt it rather than force it into the nearest template. Official external editorial/design examples may actively inform composition when they serve the subject. Record the exact source and inspection scope; keep observed design apart from proposed adaptation.

Give 2–3 meaningful alternatives, recommendation first: what the reader notices, fitness to the question, and important tradeoffs in detail/evidence/legibility/editability. A table emphasizes exact conditions; a chart emphasizes comparable magnitude. An annotated image shows the object; a diagram shows connections. Keep facts and final-language labels equivalent. Never invent data to make a chart option or redraw official assets.

Use a compact explanation/table unless the choice needs actual visual comparison. Then author only the key visual area in the canonical HTML composition at comparable size, not several complete documents. Record the chosen form/reason in the existing page map and reuse accepted choices.

## Specify only the important details

For complex visuals record the source, units/period/scope/status, encoding, essential labels/conditions and editing needs in the existing page map. Position/length/color/size/arrows must have a defensible meaning. Keep qualifiers adjacent, use common scales, distinguish unknown from zero, and label targets/projections. Do not use ornamental 3D chart effects to distort magnitude.

Generated scenes, pictograms, image panels and storyboards may be the strongest explanation. Use [generated visuals](generated-visuals.md) for creation, keeping real business labels separate/editable and concepts distinguished from evidence. An isometric scene is one possibility, not a compulsory style.

## Output and review

- **PPTX:** business text, labels, tables and simple connectors should remain editable where supported. Native charts when feasible; identify image elements accurately. Extension alone is not editability.
- **PDF/print:** actual-page legibility, visible sources, suitable image resolution and vector diagrams where useful. Verify specified print geometry.
- **DOCX:** native headings/tables/captions and robust page flow; diagrams must fit the real width.
- **HTML:** structured text, requested responsive/fixed geometry, portable assets. Static exports need a complete explanation without interaction.
- **Raster:** photographs, supplied artwork, intentional illustrations. Do not flatten editable business copy or factual labels merely for convenient export.

Use real final-language text in the first preview. Review actual rendered scales, units, arrows, grouping, image identity/crops and annotations alongside the intended takeaway. Unknown qualifications cannot be hidden to fit a layout. For line composition and Korean/Japanese breaks use [text flow](text-flow-and-wrapping.md); a clean overflow check is not a semantic or visual review.
