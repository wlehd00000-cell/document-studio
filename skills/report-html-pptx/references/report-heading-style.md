# 보고서 페이지 제목과 소제목은 명사형으로 쓴다

보고서·승인/품의·실행계획·안내/매뉴얼 등 읽기용 업무 문서의 페이지 제목과 소제목은 **짧고 구체적인 명사구**를 기본으로 한다. 본문은 자연스러운 문장으로 설명한다. ‘~합니다/~됩니다/~하였습니다/~할 수 있습니다’로 끝나는 설명문을 제목에 그대로 올리지 않는다. 일본어도 ‘～です/～ます/～します’ 등의 문장형을 소제목에 자동 사용하지 않는다.

‘추진 배경’, ‘주요 검토 사항’, ‘도입 기대 효과’, ‘검증 완료 현황’, ‘후속 실행 계획’처럼 해당 페이지의 대상과 역할을 나타낸다. ‘현황’, ‘효과’, ‘다음 단계’라는 같은 추상 제목만 모든 쪽에 반복하지 않는다. 예: ‘공급 안정성을 높일 수 있습니다’ → ‘공급 안정성 개선 가능성’, ‘검증을 완료하였습니다’ → ‘검증 완료 현황’, ‘비용 절감이 기대됩니다’ → ‘예상 비용 절감 효과’. 일본어는 ‘導入による効果を説明します’ → ‘導入の期待効果’, ‘検証を完了しました’ → ‘検証完了状況’처럼 실제 의미에 맞게 다시 쓴다.

어미만 자르거나 무조건 ‘~함/~임’을 붙이지 않는다. ‘추진합니다’에서 ‘추진’만 남겨 대상이 사라지면 핵심 대상·관계까지 다시 적는다. 기대·추정·제안·검토·미확정·완료 상태를 제목에서도 보존한다. 예상 효과를 실적처럼, 검토 중인 방안을 확정 결정처럼 쓰지 않는다. 목차·본문 제목·native PPTX 제목의 문구를 함께 맞춘다.

발표자료에서 메시지형 문장 제목을 의도적으로 선택했거나, 사용자가 문장형/원문 보존을 명시한 경우 그 범위에 맞게 적용한다. 발표용 assertion headline 규칙을 보고서 소제목에 복사하지 않는다. 보고서 본문 안의 결론 문장·인용·복사형 요청문은 소제목이 아니며 문장형을 유지할 수 있다.

brief 또는 page map에 heading_style=nominal을 기록하고, HTML의 문서/해당 페이지에는 data-heading-style="nominal"을 반영한다. message/preserve/quote는 실제 명시/용도에 근거한 좁은 예외다. 보고서 명사형은 새 스타일 질문이 아니라 기본 제작 규칙이다.

완료 전 모든 페이지 제목, h3/h4 등의 소제목, 목차와 실제 PPTX의 해당 제목을 읽는다. check_document.py의 SENTENCE_HEADING은 알려진 문장 종결형을 찾는 경고이며 명사구의 정확성이나 상태 보존을 보증하지 않는다. 경고가 없어도 실제 언어 검수를 한다.
