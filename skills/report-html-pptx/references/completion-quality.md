# 문서의 완료 품질

기존 집필·디자인·출력 검수에 적용한다. 추가 설문이나 승인 회차를 만들지 않는다. 원샷은 필요한 검수까지 진행하고, 최신 원고와 최종 파일에 확인 결과를 반영한다.

## 실제로 적용한 스킬

새 전체 문서는 구성·집필·디자인·출력을 적용한다. 조사·번역·시각자산은 실제 필요에 따라 사용한다. 기존 QA 메모 또는 `qa/skill-use.json`에 적용한 SKILL 경로/버전, 작업, 변경·확인 범위와 파일 근거를 짧게 기록한다. 조건부 스킬의 미사용은 필요하지 않은 이유를 남긴다. 이름을 계획에 적거나 파일을 읽기만 한 것은 적용 완료가 아니다. 스킬 사용 개수를 높이려고 불필요한 절차를 실행하지 않는다.

## 집필과 디자인

한국어 원고는 [원고 품질](../../document-writing/references/korean-copy-quality.md)을 적용한다. 실제 논리와 상태를 보존하고 문장 호응·연결·구체성·띄어쓰기의 통일을 본다. 새 전체 문서는 모든 페이지를 최종 크기로 읽고, 제목·본문·복사형 요청문·표·주석·하단을 빠뜨리지 않는다. 표지의 완성도가 본문 검수의 증거는 아니다. 영향 범위가 한정된 수정은 최신 상태가 유효한 나머지 검수를 재사용한다.

## 줄 흐름 경고

자동 검사에서 `status=measured`는 측정 완료이며 편집 판단 완료가 아니다. 자동 경고가 없어도 한국어 문장 연결과 실제 행을 읽는다.

프로젝트 상태가 각 후보에 부여한 `finding_id`와 page/block/modes로 대상을 식별한다. 같은 page/block/warning이 화면·인쇄에 반복되면 하나의 후보와 두 관측 모드로 묶는다. 다른 행이나 경고 내용은 별개로 유지한다.

현재 editorial 페이지 기록의 `warning_dispositions`에 다음을 남긴다.

```json
{
  "finding_id": "tf-<자동 후보 식별자>",
  "decision": "accepted",
  "reason": "실제로 읽은 해당 표현·행과 문맥상 허용하는 이유"
}
```

- `accepted`: 실제 행을 읽어 허용한 이유를 남긴다. 해당 페이지의 실제 이미지 근거가 필요하며 경고는 기록에 남긴다.
- `unresolved`: 확인 또는 수정이 남아 있다. 전달 준비를 막고 독립적인 작업은 계속한다.
- `fixed`: 수정 결과를 재측정한다. 현재 측정에 후보가 남아 있으면 고쳤다는 기록만으로 통과하지 않는다. 새 측정에서 해소된 후보는 현재 처리 대상에서 빠지고 이전 기록은 이력으로 보존한다.

전체를 확인했다는 문구, 다른 페이지의 판단, 오래된 이미지, 다른 후보의 처리로 해당 항목을 해결하지 않는다. 레이아웃·글꼴·누락 자산의 blocking 항목은 편집 허용으로 면제할 수 없다. 허용되는 표기 차이나 정상적인 줄바꿈을 점수 때문에 모두 고치지 않는다.

## 실제 출력

변환기가 만든 `text-fidelity.json`을 확인한다. 원고와 native 글자의 순서·필수 공백·텍스트 상자 범위를 대조하고, 실제 렌더에서 줄 끝·표·각주·crop을 읽는다. 문자 빈도 일치와 구조 검사는 실제 화면을 대신하지 않는다. 신규 전체 문서는 모든 최종 페이지, 수정은 영향받은 페이지와 전체 순서를 확인한다.

PowerPoint에서만 생긴 문제는 검증한 해당 문단의 변환 사본을 조정한다. `data-pptx-text-flow="measured"`는 브라우저 행을 실제 확인한 좁은 범위에만 사용하고 자연 줄바꿈을 기본으로 유지한다. 출력 전용 변경 후에도 해당 최종 페이지를 다시 렌더한다. audited HTML을 export dependency로 기록해 그 변경이 출력 검수의 freshness에 반영되게 한다.

전달에는 실제 파일, 확인된 결과와 중요한 미확인 범위를 짧게 쓴다. 저장·설치·새 채팅 로딩·사용자 수락·다른 PC·실물 인쇄를 파일 검수 완료와 구분한다.

## 의미 단위 줄내림을 먼저 판단한다

[사용자 수정에서 확인한 줄내림 기준](../../document-writing/references/semantic-linebreaks.md)을 적용한다. 안내·요청문·짧은 읽기용 설명은 문장 기능이 바뀌는 지점을 실제 줄에 반영한다. 자동 경고가 없어도 이 판단을 생략하지 않는다. 본문의 모든 마침표 뒤에 줄을 넣거나 브라우저의 모든 물리적 줄을 고정하지 않는다. 같은 기능의 문장은 이어 쓰고, 기능 전환은 독립된 읽기 단위로 시작한다. 추가 행의 높이·인접 영역·하단을 다시 확인한다. editorial/export의 `semantic_breaks` 기록에는 실제 나눈 기능 또는 나눌 필요가 없는 이유를 적는다.

## 본문 순서와 보고서 제목

[설명 방식과 전개 검수](visual-expression-and-rhythm.md)를 적용해 표 지배·같은 구도·같은 서술 움직임의 반복을 실제 순서로 확인한다. 기존 QA sequence_review에 대상 페이지, 바꾼 방식과 결과 또는 정밀 비교/의무 양식 등 유지한 이유를 남긴다. 후보 경고 해소와 실제 시각 판단을 구분한다. 보고서의 모든 페이지 제목·소제목은 [명사형 규칙](report-heading-style.md)으로 읽고 목차·원고·HTML·실제 PPTX가 같은 의미와 상태를 유지하는지 확인한다.

Follow [production contract](production-contract.md) for independent use/canvas decisions, compact next-step information, actual design measurement and verified role evidence. Existing editorial/visual/export checks remain required.

## 채택된 기본 구성의 실제 적용

새 전체 문서의 표현이 미지정이면 [가이드 구성 기본값](accepted-composition-default.md)의 실제 본문 수준을 검토한다. 표현 축 선언이나 표지 하나가 아니라 현재 원고와 연결된 이미지/도식·공간 관계·서술 진전으로 확인한다. 기존 map/sequence QA에 해당 페이지와 적용 관계, 수정 결과 또는 반복 유지 이유를 남긴다. 참고 가이드의 페이지 수·이미지 수·과거 필수 선택을 강제하지 않는다. 명시 스타일·양식·기존 채택값은 해당 범위에서 우선한다.
