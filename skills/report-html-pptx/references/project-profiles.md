# Existing projects, templates and purpose profiles

Reuse the accepted brief and interaction mode. Inspect the current canonical source and requested change; do not replay a new-document intake for small edits. Reopen only purpose/reader/language/use choices actually made uncertain by the change.

[Canonical design profiles](../system/design-system.md) share DEMO assets but differ by purpose: reading report, office print, executive approval, proposal, execution, reading deck and live deck. Values come from system/design-tokens.json; accepted template and explicit user instructions take precedence. Cover/opener/body page families have distinct density and hierarchy. There is no mandatory color band or universal ESG layout.

For an accepted PPT/Google Slides template, preserve the original and inspect its actual fixed art, fonts, canvas, footer and layout constraints. Compose the requested deliverable in HTML; identify fixed/flexible boundaries once and ask only consequential ambiguity. Reconstruct the scope needed for the requested output, preserving outside-scope visual intent. Do not promise retention of original slide masters/object IDs from HTML conversion without actual proof. Accepted HTML retains its source and relative assets. Default output uses the packaged HTML-to-PPTX converter. See [route selection](../system/authoring-routes.md).

A past document supplies reusable components and specific design relationships, not current facts, approval status or a forced page count. Preserve user-chosen line breaks and image ratios; changes trigger their affected page/output checks. Keep generated concepts distinct from evidence photographs.

Office-printer requests use [office-print](office-print-reports.md), retaining known language, purpose, page count and editability. Physical print is a separate receipt. Accepted screen assets and a supplied template remain authoritative where compatible with the print request.

Use [project-state](../system/project-state.md) to reuse valid inspections and invalidate affected dependencies; do not create duplicate revision databases. Preserve source intent and official art. Separate campaign/SNS creation remains outside this document workflow.
