# 필요한 시점에 필요한 기능만 확인한다

HTML 작성에는 변환기·Office가 필요하지 않다. 현재 자료로 원고와 HTML을 먼저 시작하고, 미리보기/내보내기를 사용할 때 해당 환경을 한 번 확인한다. 이전 실행 경로와 실패 이유는 재사용한다. 모든 출력 도구를 시작 전에 탐색하지 않는다.

[고정 경로](../system/authoring-routes.md)에 따라 기본 PPTX는 기존 HTML-to-PPTX 변환기로 만든다. 특별 PDF·HTML·DOCX 요청은 같은 HTML의 export 예외다. 기존 PPT 양식, 가용 native 기능이나 디자인 품질 판단으로 직접 제작으로 전환하지 않는다.

번들 경로 조회가 있으면 필요한 실행 환경을 한 번 찾는다. HTML 미리보기는 허용된 브라우저/렌더러를 사용한다. 변환기에는 Python·의존성·Playwright/Chromium이 필요하다. 설치·회사 설정·시스템 글꼴 변경을 자동 해결책으로 요구하지 않고 직원에게 내부 기술을 고르게 하지 않는다.

변환 기능이 없으면 HTML과 완료한 검수를 보존하고 PPTX 생성의 구체적 미완료 범위를 알린다. 실제로 필요한 새 설치나 최종 출력 변경은 구체적인 결과를 제시한 뒤 결정받는다. 자동 native 재제작이나 묵시적 형식 변경은 하지 않는다.

HTML 화면 검수와 최종 PPTX/PDF 렌더는 별개다. 앱 미리보기 실패 하나로 전체 렌더 불가를 단정하지 않되 명시적 접근 거부를 우회하지 않는다. 최종 렌더가 없으면 생성/구조/편집성 확인과 화면 미확인을 구분하고 [state](../system/project-state.md)를 unverified로 남긴다. 유용한 파일은 검토 후보로 전달할 수 있으나 ready로 쓰지 않는다.

첫 사용 안내는 요청했을 때 짧게 현재 채팅에 제공한다. 설치·계정 저장·현재 채팅 스킬 로딩·실제 파일 기능은 별개이며 자동 환영 메시지를 약속하지 않는다.

Windows 최종 검증 이미지는 PowerPoint의 고정 배치 PDF 출력과 PyMuPDF를 우선 사용한다. 직접 PNG 내보내기는 포함 글꼴을 인식했다고 표시하면서도 한일 본문 폭·굵기·잘림이 달라지는 사례가 실제 재현됐다. 포함형 글꼴만 있는 문서에서 PDF 검증 경로가 없으면 PNG와 PPTX는 후보로 보존하고 해당 글꼴 렌더링은 미검증으로 기록한다. 단순 캡처 성공이나 글꼴 이름은 완료 증거가 아니다. 기존 편집 가능한 PPTX 제작 엔진은 유지한다. 호스트의 도구를 조용히 전역 설치하거나 시스템 글꼴로 대체하지 않는다. 유효한 PDF 검증 이미지와 다른 PC의 실제 PowerPoint UI는 별도로 확인한다.
