# First use and required questions in chat

First-use help stays brief and uses the conversation language. If the task is unknown, offer new document / revise existing / translate or polish; a typed task takes precedence. Help alone does not authorize production.

If the user wants the assistant to challenge the document thesis, independently benchmark real reports, propose competing strategies and discuss representative visual samples **before writing**, offer the separate opt-in [Editorial Consulting Mode](editorial-consulting-mode.md). Do not add it as a third required `mode` answer or force it into the ordinary first-use question bundle. Its sample previews are early concept comparisons; once the author chooses a direction, editorial research/writing resumes before the existing final Design → Export route. Do not enable it without an actual author request.

For an actual new document, apply [intake](intake-and-collaboration.md) even when first-use help was not requested. Check mode, document type, audience, reader action, final language and output format. Reuse actual resolved choices and ask only missing ones in a short bundle. A topic, supplied file or generic go-ahead cannot replace the required answers. Suggested defaults and selected-but-unsubmitted options are not answers.

Apply each reply directly. Keep all unanswered fields pending across partial replies and turns, and ask only the remainder. “대충/알아서/그냥 진행/適当に/お任せ” cannot silently fill unspecified fields. Specific delegation plus a reasoned recommendation resolves only that field. Continue independent input review while waiting. Once the choices are resolved, complete the authorized one-shot task without further startup or stage approvals.

Use the host's available chat question control, with at most three concise grouped questions when needed; otherwise use a short numbered list. Follow [question waiting](question-waiting.md). After opening an asynchronous question, keep the turn active and wait for the submitted reply or explicit cancellation; a display acknowledgment is not an answer. Do not immediately send a final message. Wait checkpoints never expire a required choice. If the host cannot retain the question control, preserve pending fields and use ordinary chat. Do not discover a renderer, open HTML, invoke show_onboarding or create a page for startup. No selection-summary approval, send button, download, JSON copy or second submission is needed.

Translations, small revisions and conversions reuse the relevant accepted conditions instead of repeating a new-document interview. Taste, creativity and intensity remain optional. The production route is HTML and the default editable PPTX export; check the chosen exporter when needed. Installation, saved release, host loading and finished files remain separate states.
