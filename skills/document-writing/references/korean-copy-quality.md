# 한국어 원고의 마지막 품질 확인

집필에 포함되는 검토다. 별도 승인·외부 서비스·다른 플러그인 설치를 시작 조건으로 만들지 않는다. 기존 문서에서는 바뀐 원고와 영향받은 제목·표·주석만 다시 읽고, 좋은 문장은 유지한다.

## 원고에서 확인할 것

| 확인 | 실제 작업 |
| --- | --- |
| 의미와 상태 | 이름·수치·단위·기간·예외·확정/제안/협의/확인 상태를 원자료와 대조한다. 자연스러운 문장을 위해 상태를 강화하지 않는다. |
| 호응과 책임 | 누가 무엇을 하는지 분명한지 읽는다. 담당자와 기한처럼 성격이 다른 항목에 같은 수식어가 어색하게 걸리지 않는지 확인한다. |
| 문장 연결 | 앞 문장이 뒤 문장의 근거·조건·다음 행동과 연결되는지 확인한다. 단문을 나열하거나 비슷한 요청을 반복하는 구간만 정리한다. |
| 구체적인 표현 | 초보 직원용 안내의 ‘원본 정체성’, ‘원본의 공백’ 같은 추상 표현은 ‘로고·제품·사진의 원래 모습’, ‘필요한 원본이 없음’ 등 실제 대상과 행동으로 풀어 쓴다. 전문 독자의 정착 용어는 보존한다. |
| 띄어쓰기와 표기 | 본문·제목·표·복사형 요청문의 업무 용어와 보조 용언 표기를 통일한다. 허용되는 두 표기 중 하나를 고른 경우 오류 교정 수로 세지 않는다. 회사명·상품명·공식 명칭의 공백은 원본을 우선한다. |
| 실제 쓰는 요청문 | 친근한 요청문과 공식 본문의 말투가 각각 일관된지 확인한다. 대괄호 교체 항목, 필요한 첨부, 미확정 조건과 원하는 파일이 실제로 사용 가능한지 읽는다. |
| 표와 주석 | 표의 짧은 명사형 표현과 연결된 설명을 함께 읽는다. 가격·일정·예외를 관련 항목 가까이 둔다. 본문을 다듬고 표·각주를 누락하지 않는다. |

‘잠정 추천값’처럼 내부 절차의 용어를 직원에게 설명해야 할 때는 먼저 ‘정하지 않은 조건은 추천안으로 정하며 바꿀 수 있습니다’처럼 사용자 행동을 쓴다. 사실을 추가하거나 독자 수준과 무관하게 모든 용어를 순화하지 않는다.

## 화면에서 확인할 것

실제 한국어 [줄 흐름](demo-esg-korean-lineflow.md)을 읽는다. 띄어쓰기를 바꾼 뒤 폭·행 수·표 높이도 다시 확인한다. ‘정리해 / 줘’, ‘완성해 / 줘’처럼 본용언과 짧은 보조 용언이 갈라지거나 다음 행에 짧은 어미만 남는 구간은 문맥과 판면을 보고 판단한다. 모든 분리를 맞춤법 오류로 단정하거나 모든 문장을 강제로 묶지 않는다.

HTML과 최종 PowerPoint는 따로 읽는다. HTML의 keep-all, 줄 흐름 경고 0건, 문자가 같은 개수라는 결과는 PowerPoint의 공백·읽는 순서·줄 끝 표현이 보존됐다는 증거가 아니다. 원고 문제는 정본에, 변환 문제는 변환 사본에 반영하고 해당 최종 페이지를 다시 확인한다.

## 남기는 기록

기존 editorial 페이지 기록에 구체적인 확인과 변경 여부를 남긴다. 요구되는 범주는 `source_equivalence`, `status_conditions`, `language`, `copy_clarity`, `spacing_consistency`, `rendered_lineflow`이다. 일반적인 ‘모두 확인’ 대신 실제 표현·문장 관계·표기 기준·영향받은 행을 적는다. 상세 오탈자 목록이나 변경률 점수는 요청이 있을 때만 만든다.

검토자가 원고와 화면을 직접 읽었다는 범위로 설명한다. 외부 맞춤법 서비스, 전문 교정자 또는 사용자 최종 수락이 없으면 있었다고 말하지 않는다.

띄어쓰기 기준은 [국립국어원 한국어 어문 규범](https://www.korean.go.kr/kornorms/m/m_regltn.do)의 해당 항목을 확인한다. 보조 용언의 원칙·허용과 예외를 구분하며, 모든 붙임 표기를 일괄 오류로 처리하지 않는다. 문서의 통일 기준을 적용해도 공식 명칭과 원자료의 의미를 바꾸지 않는다. 2026.10.07 기준 확인.

## 의미 단위 줄내림을 먼저 판단한다

[사용자 수정에서 확인한 줄내림 기준](semantic-linebreaks.md)을 적용한다. 안내·요청문·짧은 읽기용 설명은 문장 기능이 바뀌는 지점을 실제 줄에 반영한다. 자동 경고가 없어도 이 판단을 생략하지 않는다. 본문의 모든 마침표 뒤에 줄을 넣거나 브라우저의 모든 물리적 줄을 고정하지 않는다. 같은 기능의 문장은 이어 쓰고, 기능 전환은 독립된 읽기 단위로 시작한다. 추가 행의 높이·인접 영역·하단을 다시 확인한다. editorial/export의 `semantic_breaks` 기록에는 실제 나눈 기능 또는 나눌 필요가 없는 이유를 적는다.
