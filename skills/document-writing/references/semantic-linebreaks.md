# 의미 단위 줄내림

2026.10.07 사용자가 직접 수정한 한국어 첫 사용 가이드에서 확인한 기준이다. 내용과 텍스트 상자 크기를 유지하면서 9개 페이지의 24개 상자에서 25곳을 추가하고 기존 줄내림 1곳을 옮겼다. 19곳은 문장 경계, 4곳은 절 경계, 1곳은 조건과 실행, 1곳은 긴 소개문의 대상구와 서술부 경계였다. 실제 새 문단 22곳과 문단 내 줄내림 3곳을 구분했으며, 모두 Shift+Enter였다고 단정하지 않는다. [전체 25개 사례](synthetic-linebreak-cases.json)는 학습 근거이며 다음 문서의 줄내림 할당량이 아니다.

## 적극적으로 나눌 조건

한국어 직원 안내, 복사형 요청문, FAQ와 짧은 읽기용 설명은 여러 문장을 한 상자에 넣은 뒤 문장 기능의 전환을 먼저 찾는다. 다음 기능이 별도의 행동·보존 조건·확인 범위를 시작하면 새 시각 행으로 시작하는 것을 기본 검토안으로 삼는다. 자동 경고나 넘침이 없어도 실행한다.

5쪽에서는 ‘가격을 구분해 줘.’ 뒤에서 새 행을 시작해 ‘편집 가능한 PowerPoint’를 함께 읽도록 바꿨다. 기존 ‘편집 가능한 / PowerPoint’ 사이의 줄내림은 없앴다. 줄을 추가하는 것과 연결된 의미를 다시 묶는 작업을 함께 수행한다.

## 연속해서 읽을 조건

같은 주체와 기능의 설명·근거·사례는 자연스럽게 이어 쓴다. 모든 마침표·쉼표 뒤에서 나누거나 매 문장을 별도 문단으로 만들지 않는다. 의미 있는 새 역할이 없는 한 문장, 짧은 표 셀, 좁은 주석을 억지로 두 줄로 만들지 않는다. 기능을 나누더라도 조사·어미·본용언과 보조 용언, 이름·수치·단위와 연결된 대상은 보존한다.

신규 문서는 현재 독자 질문과 실제 문장을 보고 판단한다. 사용자 사례의 정확한 글자 위치를 다른 폭·언어·판형에 그대로 복제하지 않는다. 일본어에는 실제 문장 기능과 금칙을 함께 적용하되 이번 한국어 표기 사례를 기계적으로 이식하지 않는다.

## 구현과 완료 조건

1. 원고의 문장 기능을 표시하고 어디를 이어 읽고 어디에서 새 기능이 시작되는지 결정한다. 내용·조건·표기·문단의 논리를 보존한다.
2. HTML의 해당 문단에만 `<br>`과 구체적인 `data-text-flow-break-reason`을 적용하거나 실제 문단 경계로 작성한다. 단순 줄내림이면 불필요한 빈 행이나 문단 간격을 추가하지 않는다. 한 읽기 단위 안은 자연 자동 줄바꿈을 유지한다.
3. 내용 자체의 문단 전환과 현재 폭에 필요한 시각 행 분리를 구분한다. 전체 브라우저 행을 고정하는 `measured` 전환은 개별 변환 문제를 검증한 범위에만 사용한다.
4. 추가 행의 실제 높이를 재계산한다. 텍스트 상자·표 행·인접 블록·하단 설명과 푸터의 겹침을 확인하고 필요한 배치를 조정한다. 내용을 지우거나 전체 글자를 줄여 줄내림 판단을 숨기지 않는다.
5. HTML과 실제 최종 PPTX를 따로 읽는다. 명시한 경계가 공백으로 바뀌거나 연결된 형식명이 갈라지지 않았는지 확인한다. `text-fidelity.json`은 명시한 줄내림의 native 보존을 확인하지만 의미 판단·가독성·글자 높이 검토를 대신하지 않는다.
6. editorial/export의 `semantic_breaks` 기록에 실제 기능 전환과 경계 또는 나눌 필요가 없는 이유를 남긴다. 자동 경고가 0건이라는 일반 문구로 이 항목을 대체하지 않는다.

사용자가 수정한 PPT가 제공되면 최신 원본을 보존한 상태로 이전 버전과 읽기 전용 비교한다. 문장 변경, 글꼴·폭 변경, 명시 줄내림, 자동 감김과 단순 저장 형식 변경을 구분한다. 검증된 의도만 일반 규칙에 반영하고 사용자 파일을 자동으로 이전 제작본으로 되돌리지 않는다.
